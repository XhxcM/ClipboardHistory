# Monolyth 风格低负载 UI 重设计

> 本文已于 2026-10-11 被 `GOAL.md`、`README.md`、`CONTEXT_SUMMARY.md` 和 `VERIFICATION.md` 取代，仅保留为历史记录，不得作为当前实现要求。

日期：2026-10-08  
状态：用户已批准对话设计，等待书面设计复核

## 1. 目标

在不改变剪贴板历史程序功能、数据格式和用户设置的前提下，将现有“静谧雾光”界面重设计为受 Monolyth 启发的高级 Windows 桌面界面。

设计必须同时满足：

- 保持高频工具的搜索、阅读和复制效率。
- 使用石墨黑、冷银灰和单一冷青强调色建立统一视觉语言。
- 用透视线路、少量信号脉冲和局部选中反馈表达空间感。
- 避免高频动画、实时模糊、粒子、鼠标跟随及其他持续负载。
- 深浅色跟随系统，并在 Windows 关闭客户端动画时提供静态表现。
- 保留现有剪贴板、快捷键、托盘、设置和安装行为。

## 2. 设计解读

这是面向高频效率用户的 Windows 剪贴板工具重设计。视觉语言冷静、未来、具有空间方向感，但不把软件做成展示型网页。

最终设计参数：

- `DESIGN_VARIANCE: 6`
- `MOTION_INTENSITY: 4`
- `VISUAL_DENSITY: 5`

参考设计的可迁移特征：

- 大面积石墨黑负空间。
- 极细、低对比的透视线路向一个视觉核心汇聚。
- 少量冷青光点承担焦点，而不是满屏霓虹。
- 宽字距、低亮度标题和克制的层级变化。
- 高级感来自方向、景深和疏密关系，不来自大量玻璃卡片。

不复制 WebGL 折射、粒子深度或鼠标响应。WPF 版本只表达相同的视觉语言。

## 3. 方案选择

### 方案 A：WPF 原生矢量与动画，采用

使用 `WindowChrome`、`Path`、渐变画刷、透明度和变换动画完成界面。静态线路和动态信号分层渲染，不增加第三方依赖。

优点：离线、轻量、可维护，符合当前项目的最少依赖原则。  
限制：不能复刻 WebGL 着色器的真实折射和三维深度。

### 方案 B：预渲染循环背景，不采用

视频或序列帧可以接近参考动画，但会扩大安装包、增加解码负载，并让深浅色与窗口缩放适配变差。

### 方案 C：WebView2 与 WebGL，不采用

可以获得接近参考的效果，但会引入新的运行时、内存占用、输入穿透和离线验证问题，不适合本地小型工具。

## 4. 窗口架构

界面由四层组成：

1. 自定义窗口外壳：使用 `WindowChrome`，不使用 `AllowsTransparency=True`。
2. 静态线路背景：预先定义并缓存的透视线路，不逐帧重新计算。
3. 动态信号层：最多 3 到 4 个光点，只动画 `Transform` 和 `Opacity`。
4. 内容与弹层：历史、设置、状态和窗口内弹层位于最上层。

默认窗口尺寸由 `560 × 700` 调整为约 `640 × 700`，最小尺寸仍需保证主操作不被裁切。

自定义标题栏必须保留：

- 窗口拖动和边缘缩放。
- 双击最大化和还原。
- 最小化、最大化、关闭。
- Windows 窗口贴靠和系统窗口菜单。
- 关闭后隐藏到托盘的现有行为。
- 自动化名称和键盘可访问性。

## 5. 主界面

### 5.1 标题栏

左侧显示应用图标、名称和低对比运行状态。右侧依次显示“设置”与系统窗口按钮。标题栏和内容背景连成同一视觉表面。

### 5.2 搜索区

- 删除独立的“搜索”标签。
- 搜索输入框高度约 46px。
- 透视线路在搜索区附近汇聚，但不穿过输入框或正文。
- 聚焦时只增强边框和附近少量线路。
- 保留 `Ctrl+F` 与窗口呼出后自动聚焦行为。

### 5.3 历史列表

记录由独立悬浮卡片改为连续分层列表：

- 默认依靠间距和极淡分隔线建立层级。
- 悬停只改变表面色和边框，不缩放、不抬升。
- 选中显示左侧冷青短线与低透明度渐变底色。
- 主文本最多两行，继续使用省略。
- 来源应用靠左，时间靠右。
- 保留双击、回车、右键菜单和选中恢复逻辑。
- 不读取来源应用图标。
- 保持列表虚拟化。

### 5.4 底部操作区

- “暂停记录”位于左侧。
- “清空全部”位于右侧，使用低饱和危险色。
- 操作区固定，历史列表独立滚动。
- 暂停后背景信号停止，线路亮度降低。

### 5.5 空状态与搜索无结果

历史为空时保留中央汇聚背景，并显示系统剪贴板图标与“复制一段文本，它会出现在这里”。不增加插画、教程卡片或额外按钮。

搜索无结果与历史为空使用不同文案，避免误导用户。

## 6. 设置页

设置页继续位于主窗口内，不创建新窗口：

- 使用返回按钮和“剪贴历史 / 设置”标题关系。
- 删除两张大型嵌套卡片，改用留白和小标题分组。
- 开机启动保持复选语义，视觉呈现为紧凑开关。
- 快捷键输入继续使用当前捕获逻辑。
- 排除应用使用紧凑列表，空状态为“未排除任何应用”。
- “移除”只在选中项上出现。
- “保存设置”固定在右下角。
- 返回、`Esc` 和保存成功后的导航行为保持不变。

## 7. 菜单与弹层

### 7.1 历史右键菜单

保留“复制”“删除”“不再记录此应用”。只调整颜色、间距、圆角和焦点状态，不添加动画或新命令。

系统托盘菜单继续使用 Windows 原生样式，不自绘。

### 7.2 清空确认

系统 `MessageBox` 替换为窗口内弹层：

- 显示将被删除的当前记录数。
- 背景变暗但不模糊。
- 默认焦点为“取消”。
- `Esc` 和点击遮罩取消。
- 只有明确点击“清空历史”才删除。
- 弹层打开时背景不可操作，关闭后恢复原焦点。

### 7.3 快捷键冲突

快捷键冲突使用同一视觉层级的提示弹层。关闭后焦点回到快捷键输入框。注册失败后恢复旧快捷键的现有逻辑不变。

## 8. 颜色与字体

### 深色

- 背景：`#0B1011`
- 表面：`#131A1C`
- 主文字：`#E8EEEE`
- 次要文字：`#929E9D`
- 强调色：`#45CDBB`

### 浅色

- 背景：`#EEF2F2`
- 表面：`#F7F9F9`
- 主文字：`#111819`
- 次要文字：`#667372`
- 强调色：`#087D72`

普通视觉只使用冷青强调色。低饱和红色仅用于不可撤销操作。字体继续使用 Windows 自带的 Segoe UI Variable，不打包额外字体。

## 9. 动效与停止规则

| 效果 | 时长 | 规则 |
|---|---:|---|
| 背景信号脉冲 | 14-18 秒一轮 | 最多 3-4 个光点，低频循环 |
| 记录悬停 | 120ms | 表面色和边框 |
| 记录选中 | 160ms | 左侧短线和浅色渐变 |
| 新记录出现 | 160ms | 单次透明度和轻微位移 |
| 主界面与设置页切换 | 160ms | 单次透明度和水平位移 |
| 弹层出现与关闭 | 140ms | 透明度和小幅缩放 |
| 深浅色切换 | 立即 | 直接替换主题资源 |

背景动画在以下状态停止：

- 窗口最小化。
- 窗口隐藏到托盘。
- 程序暂停记录。
- Windows 关闭客户端动画。
- 截图和自动验证模式。

恢复时从静态状态重新开始，不追赶隐藏期间的动画。

禁止鼠标跟随、3D 倾斜、实时模糊、粒子、每条记录常驻动画、按钮弹跳、滚动视差和高频闪烁。

## 10. 性能预算

- 改造前记录当前版本在可见、最小化和托盘隐藏状态的 CPU 与工作集基线。
- 改造后使用相同数据量和窗口状态测量 60 秒。
- 可见静止状态平均 CPU 不高于旧版基线超过 0.5 个百分点。
- 最小化和托盘隐藏后无持续动画负载，CPU 回到接近空闲。
- UI 改造导致的工作集增长控制在约 15 MB 内。
- 搜索、滚动、选择、拖动和缩放不得出现明显卡顿。

现有每条记录上的 `DropShadowEffect` 和多组放大动画将被移除。视觉负担集中到一个共享背景和当前交互项。

## 11. 可访问性

- 所有标题栏按钮和操作按钮提供自动化名称。
- 焦点状态同时使用边框和颜色，不只依赖颜色。
- 弹层打开后焦点不能进入背景内容。
- 标题栏按钮保留足够的鼠标命中区域。
- 正文、次要文字、按钮和输入框满足 WCAG AA 对比度。
- 系统关闭动画时提供完整静态界面。
- `Esc`、`Enter`、`Ctrl+F`、方向键和右键键盘操作继续有效。

## 12. 功能与数据边界

本次不得改变：

- 历史 JSON 格式和 `%LocalAppData%` 保存位置。
- 72 小时清理、去重、搜索和排序逻辑。
- 用户快捷键、开机启动和排除列表。
- 单实例、托盘、剪贴板监听和 1 MB 文本上限。
- 双击、回车、右键复制和删除行为。
- 当前用户已经关闭的开机启动设置。

本次不修改安装向导语言，不增加产品功能，不引入新依赖。

- `src/ClipboardHistory/MainWindow.xaml.cs`：标题栏命令、弹层状态、动画暂停和恢复。

- `artifacts/screenshots/`、`artifacts/publish/`、`artifacts/installer/`：重新生成交付物。

不修改历史存储、设置持久化、剪贴板监听和安装器逻辑，除非构建验证证明现有调用因窗口改造而必须适配。

## 14. 验证与完成标准

验证顺序：

1. 记录改造前性能基线。
2. 完成窗口与资源修改。
3. 更新并运行最小 UI 自检。
4. 运行 Release 构建和自动自检。
5. 生成浅色与深色的主窗口和设置页截图。
6. 检查空状态、搜索无结果、暂停、右键菜单和两个弹层。
7. 验证拖动、缩放、最大化、最小化、关闭与窗口贴靠。
8. 验证键盘焦点和快捷键路径。
9. 重测 CPU 与工作集并和基线比较。
10. 重新生成自包含程序和安装包。
11. 验证重新安装不覆盖用户设置。
12. 更新验证记录、截图和 SHA-256。

完成必须满足：

- 深浅色使用统一的 Monolyth 视觉语言。
- 阅读区域没有干扰正文的线路。
- 自定义标题栏的原生窗口行为正常。
- 所有原有功能和用户设置保持不变。
- 两个弹层支持完整键盘操作。
- 性能符合第 10 节预算。
- Release、自检、自包含发布和安装包构建成功。
- Windows 11 完成实际验证。
- Windows 10 和当前环境无法覆盖的 DPI 继续明确标记为未验证。

## 15. 已知风险

- WPF 原生矢量只能表达参考的构图和氛围，不能复刻 WebGL 着色器质感。
- 自定义标题栏需要重点验证 DPI、窗口贴靠、系统菜单和焦点行为。
- 窗口内弹层必须正确隔离背景焦点，避免键盘穿透。
- Windows 10 与其他 DPI 的真实视觉验证仍受测试环境限制。
